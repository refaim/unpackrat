Version 0.3.5
-------------
 * Creates Unity objects through resource-specific callbacks; the universal
   full-importer factory is absent from the actual NativeAOT machine code.
 * Keeps the same version-aware reader, dependency and legacy-probe
   behavior, and export families.
 * Closes the root stream through its own lifetime; regression-tested.

Version 0.3.4
-------------
 * Stores resource names as primary strings; creates temporary UTF-8 adapters
   only when the upstream name interface requests them.
 * Reuses traversal frames in the pinned AssetsTools.NET iterator adaptation,
   preserving its field order, alignment, reset and error behavior.
 * Preserves resource names, original paths, catalogue counts and lazy exports.
 * Against frozen 0.3.3, controlled native C++ comparisons measured median
   first Hole House open at 1.8198 -> 1.6826 s (CPU 2.0703 -> 1.8125 s);
   separate Python peak-commit controls measured 427.1 -> 359.9 MB.
   Femboy stayed near flat at 0.4000 -> 0.3906 s; its peak commit increased
   from 45.6 to 46.2 MB (+1.3%). These results do not promise a universal gain.
 * The three-version comparison used all six orders and six fresh processes
   per version/game, excluding warmups. OS cache was untouched, without forced
   GC or cross-open application caching; Python timings are not native evidence.
 * Separate 12-cycle controls reached maximum process peak commit of
   480.9 -> 452.5 MB for Hole House and 70.6 -> 64.1 MB for Femboy; all 48
   full catalogue hashes matched. One process per version/game was tested.
   These maxima differ from fresh-process medians; the scope ends at 12 cycles.
 * Remains an experimental candidate for manual testing.

Version 0.3.3
-------------
 * Reuses a managed metadata reader and bounded stream for each metadata shape;
   releases the borrowed input reference after both successful and failed reads.
 * Nested bounded streams lease the captured source or view directly to shorten
   wrapper chains, preserving independent positions, bounds and lifetimes.
 * Reads UTF-8 names through bounded stack scratch and pooled buffers for larger
   strings, preserving short reads and replacement of invalid UTF-8 sequences.
 * Builds files with fallback {Type} paths immediately, retaining temporary rows
   only for original paths that need catalogue-wide collision checks. Catalogue
   order, names and declared sizes are preserved.
 * Preserves the complete catalogue and lazy resource exports. In a controlled
   comparison against frozen 0.3.2, median Hole House open time in the native C++
   host was 2.2772 -> 2.1193 s; separate Python controls measured peak commit of
   483.6 -> 427.6 MB. Femboy timing stayed similar; peak was 48.9 -> 45.8 MB.
   Against the intermediate candidate, the final candidate's first Hole House
   open used 3.94% more wall time and 5.21% more CPU time; these observations
   do not promise a universal speedup.
 * Remains an experimental candidate for manual testing.

Version 0.3.2
-------------
 * Skips unsupported objects while retaining dependencies needed for resource
   exports and original paths. Zero and duplicate object IDs are still rejected.
 * Releases redundant source-object descriptors after importing the lazy graph.
 * Prebinds metadata fields to storage slots, avoiding repeated path lookups
   while reading their values.
 * Reuses resource identities as export views and stores immutable catalogue
   values in arrays sized to the entry count, avoiding separate wrapper objects.
 * Releases temporary projections and atlas indexes across the graph, including
   dependencies, after all selected resource views have been built.
 * Hole House diagnostics measured 134.6 MB of live managed data. Fresh-process
   native peak commit increased from 469.0 to 503.6 MB after this compaction;
   opening timings stayed similar.
 * Remains an experimental candidate for manual testing.

Version 0.3.1
-------------
 * Builds the resource catalogue from metadata. Resource bodies are parsed
   only when extracted, together with the dependencies needed for that export.
 * Reads UnityFS bundle data by block instead of loading every internal file
   in full. Resource types, original paths and declared sizes are preserved.
 * Stores catalogue metadata compactly and uses adaptive Server GC with memory
   conservation on x64 to reduce memory use across repeated archive opens.
 * The x86 candidate passed 11 resource fixtures on Windows XP SP3.
 * Remains an experimental candidate for manual testing.

Version 0.3.0
-------------
 * Exports additional resource types, each through its own output file
   extension: Texture2D and Sprite to PNG, TextAsset to .bin with the original
   bytes, AudioClip to WAV or Ogg, embedded fonts to TTF/OTF/TTC, VideoClip and
   MovieTexture to their stored container, and Mesh geometry to GLB.
 * Keeps the original resource hierarchy with a literal {Type} fallback, and
   converts entries on demand.
 * No published release yet: a development-branch candidate; local builds are
   experimental manual-test builds shared directly, not public downloads.

Version 0.2.0
-------------
 * Keeps the original Unity resource hierarchy, with a literal
   {Texture2D}/{TextAsset} fallback when it is unavailable.
 * Size and PackedSize report the declared source length (0 means unknown);
   texture conversion stays lazy.
