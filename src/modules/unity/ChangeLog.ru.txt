Версия 0.3.4
-------------
 * Имена ресурсов хранятся как основные строки; временные UTF-8 адаптеры
   создаются только по запросу соответствующего upstream-интерфейса имён.
 * Кадры обхода повторно используются в адаптации закреплённого итератора
   AssetsTools.NET. Порядок полей, выравнивание, сброс и поведение ошибок сохранены.
 * Имена ресурсов, исходные пути, число записей и ленивое извлечение сохранены.
 * В контролируемом сравнении с замороженной 0.3.3 медиана первого открытия
   Hole House через нативный C++-host составила 1,8198 -> 1,6826 с
   (CPU 2,0703 -> 1,8125 с), peak commit отдельных Python-контролей —
   427,1 -> 359,9 МБ. На Femboy время осталось близким: 0,4000 -> 0,3906 с,
   а peak commit вырос с 45,6 до 46,2 МБ (+1,3%). Универсального выигрыша нет.
 * Для трёх версий проверены все шесть порядков и по шесть свежих процессов
   на версию/игру без прогревов в сводке. Системный кеш не очищался,
   принудительного GC и межсеансового кеша приложения нет. Время Python
   не использовано как доказательство нативного ускорения.
 * В отдельных 12-цикловых контролях максимальный peak commit процесса —
   480,9 -> 452,5 МБ на Hole House и 70,6 -> 64,1 МБ на Femboy; все 48 полных
   хешей каталогов совпали. Проверен один процесс на версию/игру. Это максимумы
   процесса, а не медианы свежих запусков; вывод ограничен 12 циклами.
 * По-прежнему экспериментальный кандидат для ручного тестирования.

Версия 0.3.3
-------------
 * Для каждой формы метаданных повторно используются managed-reader и поток
   с ограниченными границами; ссылка на заимствованный вход освобождается
   после чтения как при успехе, так и при ошибке.
 * Вложенные ограниченные потоки напрямую удерживают исходный источник или
   представление, сокращая цепочку обёрток. Независимые позиции, границы
   и время жизни сохранены.
 * UTF-8 имена читаются через ограниченный буфер в стеке и пул для больших
   строк. Сохранены короткие чтения и замена некорректных UTF-8 последовательностей.
 * Файлы с запасными путями {Type} формируются сразу; временные записи остаются
   только для исходных путей, требующих общей проверки коллизий. Порядок
   каталога, имена и объявленные размеры сохранены.
 * Полный каталог и ленивое извлечение ресурсов сохранены. В контрольном
   сравнении с замороженной 0.3.2 медиана открытия Hole House через нативный
   C++-host составила 2,2772 → 2,1193 с, peak commit отдельных Python-контролей —
   483,6 → 427,6 МБ. На Femboy время осталось близким, пик — 48,9 → 45,8 МБ.
   Относительно промежуточного варианта первое открытие Hole House итоговым
   кандидатом заняло на 3,94% больше времени и на 5,21% больше процессорного
   времени; универсального ускорения эти замеры не обещают.
 * По-прежнему экспериментальный кандидат для ручного тестирования.

Версия 0.3.2
-------------
 * Неподдерживаемые объекты пропускаются; зависимости для извлечения ресурсов
   и исходных путей сохраняются. Нулевые и повторяющиеся ID объектов по-прежнему
   отклоняются.
 * После импорта ленивого графа освобождаются лишние дескрипторы исходных объектов.
 * Поля метаданных заранее связываются со слотами хранения, без повторного поиска
   пути при чтении значений.
 * Ресурсные объекты служат представлениями для экспорта без отдельных обёрток;
   каталог хранит неизменяемые значения в массивах по числу записей.
 * После построения всех выбранных представлений освобождаются временные проекции
   и индексы атласов во всём графе, включая зависимости.
 * Диагностика Hole House показала 134,6 МБ живых managed-данных. После этого
   уплотнения peak commit свежего нативного процесса вырос с 469,0 до 503,6 МБ;
   время открытия осталось близким.
 * По-прежнему экспериментальный кандидат для ручного тестирования.

Версия 0.3.1
-------------
 * Каталог ресурсов строится по метаданным. Содержимое ресурса разбирается
   при извлечении вместе с необходимыми для этого зависимостями.
 * Данные бандлов UnityFS читаются по блокам без полной загрузки каждого
   внутреннего файла. Типы ресурсов, исходные пути и объявленные размеры сохранены.
 * Метаданные каталога хранятся компактно; адаптивный Server GC с экономией
   памяти снижает её расход на x64 при повторном открытии архивов.
 * x86-кандидат прошёл 11 ресурсных тестовых примеров на Windows XP SP3.
 * По-прежнему экспериментальный кандидат для ручного тестирования.

Версия 0.3.0
-------------
 * Экспорт дополнительных типов ресурсов, каждый - в собственное расширение
   выходного файла: Texture2D и Sprite в PNG, TextAsset в .bin с исходными
   байтами, AudioClip в WAV или Ogg, встроенные шрифты в TTF/OTF/TTC,
   VideoClip и MovieTexture в исходный контейнер, геометрия Mesh в GLB.
 * Сохраняется исходная иерархия ресурсов с буквальным запасным вариантом
   {Type}; конвертация записей выполняется по требованию.
 * Публичного релиза пока нет: кандидат в ветке разработки; сборки -
   экспериментальные варианты для ручного тестирования, передаются
   напрямую.

Версия 0.2.0
-------------
 * Сохраняется исходная иерархия ресурсов Unity; если она недоступна,
   используется буквальный запасной вариант {Texture2D}/{TextAsset}.
 * Size и PackedSize сообщают объявленную длину источника (0 означает
   неизвестно); конвертация текстур по-прежнему ленивая.
